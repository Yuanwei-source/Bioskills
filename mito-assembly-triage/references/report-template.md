# 线粒体组装与注释用户报告模板

本模板用于让研究者决定：当前结果可以用于什么、哪些用途应暂缓、继续复核或补测最值得解决什么。报告不是流水账，也不以一个综合分数代替生物学判断。每份真实样本交付都按以下章节和顺序填写；无相关数据时保留栏目并写 `未评估` 及原因，不删除栏目、不把未知写成通过。

## 固定报告结构

### 标题与样本信息

记录样本标识、用户提供的物种名、任务日期、报告版本。列出输入文件名及其角色（组装、现有注释、reads、参考注释）；区分样本身份信息与注释供体/参考物种。提供序列长度、FASTA record ID、模糊碱基数和必要的输入/交付 SHA-256。缺少样本来源字段时写明未提供，不推断。

### 首页关键结果

紧接标题与样本信息，先用紧凑表格呈现读者最需要判断的结果，不能把这些信息埋在正文或只放在交付文件里。至少包括：

| 主题 | 必须显示的信息 |
|---|---|
| FASTA 组装 | record 数、每条序列的 ID 与长度（bp）、模糊碱基数、当前拓扑标记及闭环证据结论；多条序列逐条列出长度。 |
| 注释结果 | CDS、tRNA、rRNA 数；遗传密码表及其确认状态；关键完整性问题；注释质检硬错误数与待核查数。若出现链向/方向疑点，必须列出具体基因、对照依据和结论；不能只抄正负链数量警告。 |
| reads/结构证据 | 有 reads 时显示样本支持范围的核心指标和限制；无 reads 时明确写“未评估”。显示尾首连接/物理闭环是否得到支持，不把线性化记录写成已闭环。 |
| 使用判断 | 明确的总体建议状态，以及最重要的一项限制。 |

表格后用三行短句明确：**主要发现**、**本次实际处理**（包含“未改动”）、**仍未解决**。对证据不足的数据写“未评估/未解决”，不得留空或暗示通过。避免一行塞入过多数字；具体分析仍在后续章节展开。

链向检查须区分“负链编码”（常见且正常）、整条序列反向互补（表示方向差异）、单个基因与可比近缘参考链向不一致（需调查），以及基因集不完整造成的链数量偏差。链数量只能作为筛查线索；报告须给出逐基因对照。缺少适用近缘参考时明确写未能判定，不得仅凭通用排列自动翻转注释。

### 1. 结论与使用建议

用不超过一个短段落说明当前结论，再用表格给出面向实际用途的建议。必须选择一个总体建议：

| 建议状态 | 含义 |
|---|---|
| **可继续使用** | 对明确列出的用途，关键证据足够；仍须说明不在结论范围内的事项。 |
| **有条件使用** | 可用于指定的探索性/局部分析，但列出的缺口会影响其他用途；说明继续使用的条件。 |
| **建议暂停并补证据/补测** | 关键组装或注释问题足以使预期分析结果不可靠；说明最具判别力的补充证据。 |

| 目标用途 | 建议 | 条件/限制 |
|---|---|---|
| 指定基因或局部序列分析 |  |  |
| 全线粒体比较/系统发育 |  |  |
| 基因组成、基因顺序或 RNA 生物学 |  |  |
| 提交数据库/作为完整参考基因组 |  |  |

只评价用户可能关心的用途。不要因某一用途受阻就笼统说整个样本“不能用”，也不要把“可用于探索”写成“适合发表/提交”。

### 2. 本次检查范围与数据

列出实际输入及样本对应关系、测序平台/读长/文库、reads 是否可用、物种和遗传密码表及确认状态。用一张小表区分已检查、部分检查、未检查；标明未检查项目对结论的限制。参考序列/供体注释仅作为证据来源之一，不应和样本数据混为一谈。

### 3. 结果概览

组装与注释分开描述，不合成为单一分数。至少概述：组装记录数与长度、N/IUPAC 模糊碱基、候选连接/拓扑证据；CDS/tRNA/rRNA 注释数、关键完整性/身份/边界问题；reads 支持检查的覆盖范围和主要限制。每个结论使用下列证据状态之一：

- `SUPPORTED`：本次证据支持该明确命题。
- `SUPPORTED_WITH_CAVEATS`：有支持，但适用范围或关键限制会影响其他用途。
- `UNRESOLVED`：有歧义、冲突或缺少区分解释的证据。
- `NOT_ASSESSED`：本次没有做该检查；不是阴性结果。

可以同时报告不同层级的命题，例如“序列与现有 reads 相容”与“物理闭环未验证”。不要把低覆盖直接称为组装错误、没有 reads 证据称为 reads 不支持，或注释器未检出称为真实基因丢失。

### 4. 发现、处理与处理后结果

按 **组装问题** 和 **注释问题** 分组。每个问题使用独立编号，并在表格中闭合证据链：

| ID/位置 | 观察到的问题 | 证据及反证 | 处置与实际修改 | 复验结果 | 状态/置信度 |
|---|---|---|---|---|---|

`处置` 必须明确为已修正、保留不改、仅生成候选或未解决。修改项同时列出修改前/后值；没有修改时写“未修改”并说明依据。置信度针对该条命题，附理由；不能只给总置信度。若用参考同源性、软件预测或人工判断，说明它支持的命题及不能支持的命题。

### 5. 修改后验证与交付质量检查

按实际执行情况列出 FASTA/GenBank 序列一致性、GFF3 seqid/坐标/strand/phase/唯一 ID 和语法检查、注释质检、reads 回贴/局部证据、连接验证。逐项标 `通过`、`待核查`、`未执行`；引用 `intermediate/` 中的文件。工具返回码为 0 只说明相应软件检查通过，不是整个基因组正确的证明。

### 6. 未解决事项与推荐下一步

按优先级列出最多五项，逐项说明：未解决的具体问题、为什么当前数据区分不了解释、什么新增数据/检查最能改变结论、可能改变报告中的哪项用途建议。区分“可由现有数据继续分析”与“需要新测序/样本元数据”。若无需继续检查，说明停止理由。

### 7. 交付文件

链接根目录的 FASTA、GFF3、GenBank 和本报告；说明各自用途及关键警示。日志、BAM、自动注释原始输出、命令和 QC 等追溯材料只链接到 `intermediate/`，不塞进主结论。

### 8. 方法与复现信息

简要记录会影响判断的工具及版本、核心参数/阈值、输入匹配依据、重复处理状态和分析日期；完整命令与日志放 `intermediate/`。来源注释/参考记录及其角色也在此列出。不得用一个参考命中或一个连续性/完整性指标替代样本 reads 和结构证据。

## 报告判读规则

- 总体建议是**用途相关的决策**，不是对样本好坏的绝对评分。
- 观察、推断和采取的动作分开写；每项修改都要有证据、复验结果和可追溯位置。
- 结论必须覆盖证据不足、反对证据和未测项；`未发现` 不等于 `已排除`。
- 不以 N50、基因数量、BUSCO 分数、单工具结果或“circle”标签独自判断线粒体组装正确。BUSCO 评估的是预期保守单拷贝直系同源基因集，不直接验证样本线粒体的碱基、连接或拓扑。
- 报告简明呈现决策相关信息；长日志、逐条程序输出和命令细节留在 `intermediate/`。

## 参考依据

- [NCBI: Submitting Mitochondrial and Chloroplast Genomes to GenBank](https://www.ncbi.nlm.nih.gov/genbank/organelle_submit/)：线粒体提交准备、feature table 与注释合理性检查。
- [NCBI: Submission of annotation using a feature table](https://www.ncbi.nlm.nih.gov/genbank/feature_table/)：受控 feature/qualifier 与坐标格式。
- [QUAST 原始论文](https://pmc.ncbi.nlm.nih.gov/articles/3624806/)：组装质量需多指标审视，连续性统计可能掩盖误组装。
- [BUSCO 用户指南](https://busco.ezlab.org/busco_userguide)：完整性指标的对象是预期保守直系同源基因集；它不单独验证单个线粒体分子的组装真实性。
