# 诊断决策层（分流 / 优先级 / 停止条件）

> 本文件回答四个"先做什么"的问题：
> **① 这个异常该怀疑组装还是注释？② 检查的优先级？③ 什么时候停止？④ 谁有权做决定？**
> 证据门槛见 `evidence-standard.md`；注释判据见 `annotation_quality.md`；入口见 `START_HERE.md`。

## 1. 组装问题 vs 注释问题（最容易走错的一步）

同一个现象（如"缺一个基因"）在两条路线上的**修复动作完全不同**，而且分流错了，后面所有检查都不会改变结论：

- 路线 A（注释问题）→ 重新注释 / 补注释 / 换密码表；
- 路线 B（组装问题）→ 局部修复 / 重新组装 / 补 reads / 接受未闭合。

**判据不是"哪个解释更省事"，而是证据落在哪一侧。**

### 1.1 判定表

| 观测组合 | 优先怀疑 | 首选动作 |
|---|---|---|
| reads **连续覆盖**整个基因区 + 基因**边界**异常（起点/终点/`codon_start`/`transl_except`） + 邻近基因正常 | **注释** | 重译原始坐标、换参考重注、查 `/transl_except`（路线 A） |
| 同源蛋白/近缘参考对**同一区段**有连续支持 | **注释** | 同上；不要先动序列 |
| 局部 **zero coverage**（该基因区无 reads） | **组装/数据** | 看端部与重复，`depth_analysis.py` 定位（路线 B） |
| **split gene**：同一基因被拆到多段 / 多个 contig，且断裂点落在低覆盖或重复区 | **组装** | 检查接缝与重复塌缩，必要时 `circularize.py` |
| **repeat-associated high depth**：局部深度显著高于全局单拷贝深度 | **组装/来源归属** | 去重对照 + 竞争参考；**不得**直接判为"多拷贝"（见 `evidence-standard.md` §3） |
| **abnormal soft-clip**：末端大量 soft-clip + 低覆盖 | **组装/表示** | 检查末端唯一性与长度异质性（控制区常见正常现象） |
| 两侧证据都成立（如：有连续 reads，但该区又是低覆盖+重复） | **`UNRESOLVED`** | 写清"最少还需什么证据"，见 §3 |

### 1.2 三条硬规矩

1. **不能只用注释工具回答组装问题**：`annot_check.py` / MITOS2 的输出再一致，也不证明序列结构正确。
2. **不能只用组装工具回答注释问题**：重组装一遍不会修掉"密码表选错"或"边界差几个碱基"。
3. **判断"缺基因"前，先证明"不是没注释上"**：漏注释、命名退化、工具灵敏度与真实丢失是四个不同结论。

## 2. 诊断优先级（先结构，后注释，最后生物解释）

多数情况下**结构真实性问题优先**：组装若错，注释一致性全部失去意义。

| 层 | 内容 | 为什么在这个优先级 | 典型工具 |
|---|---|---|---|
| **P0 结构真实性** | 覆盖与零覆盖缺口、接缝/环化证据、末端低覆盖、重复塌缩、污染/NUMT 来源 | 决定后面一切结论是否可信 | `depth_analysis.py`、`circularize.py`、竞争参考比对 |
| **P1 注释一致性** | CDS 数量/身份/边界/翻译、tRNA/rRNA、重叠、链分布、基因顺序 | 在 P0 可接受后才有解释价值 | `annot_check.py`、`blast_genes.py`、MITOS2/MitoFinder |
| **P2 生物学解释** | 真实基因丢失、重排、结构退化、适应性解释 | 只有在 P0/P1 都排除技术原因后 | 文献 + 类群比较 |

**例外**：当异常本身就是纯注释问题（如密码表选择、`codon_start` 自相矛盾），P1 可以先做，但必须说明
**P0 尚未验证**，不得据此宣称组装结构已确认。

## 3. 停止条件：什么时候不用再查

诊断的稀缺陷阱是"继续跑更多工具"。**停止是需要理由的，继续也是。**

| 停止类型 | 触发条件 | 输出 |
|---|---|---|
| **Stop A：关键输入缺失** | 无 reads / 无可用参考 / 无核基因组或竞争参考 | **按结论类型分别限制**（不设全局上限，见 `evidence-standard.md` §2.1）：① 碱基正确性、接缝/闭环 → `not_assessable`；② NUMT/来源归属 → 不得称已排除，保持 `UNRESOLVED`；③ 与缺失输入**无关**的注释身份/边界结论**不受影响**，仍可 `RESOLVED`（只是 `reads_support = NOT_ASSESSED`）。同时写明"缺哪一项输入才能推进"；**不要**用"工具没报错"代替证据 |
| **Stop B：边际收益为零** | 已有关键证据组合（如：零覆盖缺口 + 重复关联高深度 + 末端低覆盖+soft-clip），再跑同类工具**不会改变结论** | 停止，直接进 DECIDE；列出已排除的解释 |
| **Stop C：只能穷举、无法判别** | 多条竞争解释需要不存在的数据才能区分 | `UNRESOLVED` + 写清"最少还需什么证据" |
| **Stop D：低功效阴性** | 观测区域覆盖太低（如 <5×），阴性结果不具判别力 | 把阴性结果记为**弱证据**，不作为独立结论（见 `evidence-standard.md` §3 阴性证据强度） |

反面清单（不构成继续的理由）：想跑完所有工具、想让报告"看起来完整"、已有结论但想再确认一遍而该确认不会改变
置信档位。

## 4. 谁来做决定（AI / 人工边界）

`REVIEW` 不是一个黑箱状态——**必须写明由谁决定**。默认规则：

| 级别 | 含义 | 典型事项 |
|---|---|---|
| **`AUTO`** | AI 可以自行判定并记录，只需留证据 | 统计量、格式/坐标一致性、GC/长度/窗口异常、partial CDS 标记、重叠 INFO、链分布表示差异 |
| **`ASSIST`** | AI 整理证据与候选，由人确认 | tRNA 身份、边界微调、参考选择、顺序差异解释、候选修复的具体坐标 |
| **`EXPERT`** | **必须**人工；AI 只能提出问题与证据 | 真实基因丢失、新结构/重排、环化认定、NUMT 来源归属、"该组装是否可用"、任何影响论文结论的声明 |

落地：每条异常在 `case.json` 的 `anomalies[]` 里除 `status`/`confidence`/`reads_support` 外，
在 `claim` 或事件里写明**决定级别与判定人**；`EXPERT` 级事项未获人工确认时，状态保持 `UNRESOLVED`。

## 5. 参考选择等级（"近缘"到底多近）

参考的**距离**决定它能支持什么结论；拿远缘参考判断边界是最常见的隐蔽错误。

| 等级 | 参考 | 可用于 | **不可**用于 |
|---|---|---|---|
| L1 | 同种既往组装（同个体/同种群） | 边界、顺序、控制区长度、tRNA/rRNA 结构 | 直接当样本序列（仍只是参考） |
| L2 | 同属 | 边界（谨慎）、顺序、tRNA/rRNA、同源检索 | 边界碱基级真值 |
| L3 | 同科 | 顺序、基因身份、tRNA/rRNA、CDS 长度量级 | 边界判断、控制区长度 |
| L4 | 同目 | 基因身份、顺序**块**级比较、异常筛查 | 边界、顺序细部（目内重排常见） |
| L5 | 远缘后生动物 | 基因身份、密码表/结构背景、缺失基因的"是否为类群常见" | 顺序、边界、长度、任何"应该有几个"的数量论断 |

规矩：
- **参考注释自身也可疑**（包括提交到公共库的记录）：它只是对照线索，不是真值；
- 记录参考的 **accession/版本/类群**；跨类群使用时标注为外推；
- 内部锚点排列（`standard_gene_order.md` §4 的 `ORDER`）**不是**未知昆虫的真实排列参考，仅用于
  fixture 测试与昆虫背景警示（见该文件 §4 的隔离说明）。

### 5.1 参考从哪来、要登记什么

**下载公共参考 ≠ 上传样本**：拉取公共参考序列不需要单独的上传授权，但每条参考都必须可回溯。

1. 优先用**已有**资源：`MITOS2_REFDIR` 的 RefSeq 库、上次案例用过的参考、单位内部参考（记录来源）；
2. 需要新取时，按 §5 等级从公共库（NCBI Nucleotide/RefSeq、Ensembl Metazoa 等）选一条**已注释**记录
   —— 必须有 CDS/tRNA/rRNA，否则无法用于顺序与边界对照；
3. **登记**（否则该参考不构成可核验证据）：accession **+ 版本号**（如 `NC_060773.1`）、检索日期、类群、
   文件 SHA-256（用 `case-init --input reference_gb <path>` 或事件记录落盘）；
4. 参考文件只作对照数据，**不覆盖**样本序列，也不得当真值（参考自身的注释同样可质疑）；
5. **发出去才是要授权的动作**：向公共库上传**样本**序列（如 `cox1_id.py`）必须先取得显式许可（默认不允许）。
   下载与上传是两个独立动作，不要互相代替。

## 6. 最小充分证据集（最少做什么就够）

"能做很多检查"不等于"都需要做"。下表是**判定某类结论的最低配置**；达不到就写明缺哪项。

| 要判定的结论 | 最低证据 | 不满足时 |
|---|---|---|
| 是否完整线粒体基因组 | FASTA + 注释 + **覆盖**（P0 结构证据） | 缺覆盖 → 完整性 `UNRESOLVED`（`not_assessable`） |
| 是否环化 | 端部**唯一**序列 + **跨接缝 reads**（独立分子数、MAPQ、链向）+ 排除重复方案 | 缺跨接缝 reads → 保持候选结构，不得宣称闭环 |
| 基因是否真实缺失 | 注释失败 + **全长同源检索** + 局部 reads/contig 结构 | 缺同源或局部证据 → `UNRESOLVED`（`UNDETERMINED_TRNA` 类情形见 `annotation_quality.md` §3） |
| 单碱基是否正确 | 原始 reads pileup：深度 + MAPQ + 碱基质量 + 链向（四项全过） | 任一项不过 → 不写入最终序列 |
| 是否 NUMT 来源 | **竞争性参考证据**（核/其他位点） | 无竞争参考 → 只能是受限的 `READS_CONSISTENT`，结论 `UNRESOLVED` |
| tRNA 是否缺失 | 反密码子/结构 + 同源 + 邻域（多工具一致） | 仅一个工具未发现 → 只能记"未检出"（`annotation_quality.md` §3 等级 B） |
