# 结果交付约定

用户要的是当前数据下最可信的线粒体组装和注释结果，以及说明问题和处理过程的最终报告。每个样本使用一个简洁的交付目录：

```text
<样本名>_mitogenome/
├── <样本名>_assembly.fasta
├── <样本名>_annotation.gff3
├── <样本名>_annotation.gb
├── <样本名>_report.md
└── intermediate/
    ├── logs / QC / 比对文件
    └── 自动注释原始输出 / 其他复核材料
```

目录根部只放四个主要交付物。报告详细列出发现、实际修改、修改依据、验证结果和仍未解决的问题；不额外要求用户查找单独的修改清单。中间文件供追溯，默认无需用户逐个查看。不要将原始 FASTQ 大文件复制进交付目录。

## 四个主要文件

1. **FASTA**：交付经审核的最佳当前组装候选。若没有证据支持碱基或结构修改，可交付输入的只读副本；报告须说明是否原样保留，以及 N、歧义区或连接支持的状态。
2. **GenBank**：主注释记录，保存 source、feature qualifiers、partial 状态、例外和注释来源。用户只有 FASTA 时可先运行适用的注释器，但自动输出只是候选，必须复核基因身份、边界、翻译、RNA 注释和类群适用性。
3. **GFF3**：与 FASTA seqid 一致，便于常见基因组浏览器及分析流程使用。优先调用已安装的成熟格式转换器（如 BioPerl `bp_genbank2gff3`），不要为常规格式转换另写解析器。转换后核对 CDS phase 与 `/codon_start`、非 CDS phase、方向、坐标、序列 ID、唯一 ID、拓扑声明和 assembly gap。转换器的格式问题可做明确、可复现的后处理，并在报告中说明。
4. **Markdown 报告**：按[固定报告模板](report-template.md)填写。开头给出用途相关的继续/有条件继续/暂停建议，再交代数据范围、组装与注释概况、逐项问题—证据—处置—复验链、尚未解决的问题、下一步和复现信息。报告应让用户判断当前结果能用于什么，以及补测是否值得。

## 三种输入场景

- **只有组装 FASTA**：检查序列记录、长度、歧义碱基与可见异常；在密码表和适用注释工具明确后生成注释候选，再做联合复核。缺少 reads 时，不把碱基或闭合真实性说成已验证。
- **已有组装和注释**：核实二者序列和样本信息匹配，然后联合检查组装、注释与可用 reads；只对证据支持的问题生成修订候选。
- **只有原始 reads**：先核对平台、读长、单双端/文库和样本信息，再选择匹配的成熟组装工具。GetOrganelle 的 reads 路线用于 Illumina 单端/双端 FASTQ，动物线粒体可用 `animal_mt` 数据库；初始化方法、输入范围和输出图文件见[上游文档](https://github.com/Kinggerm/GetOrganelle)。长读长或混合数据应选用与平台及项目目标匹配的工具，不能把 Illumina assembler 用于原始 ONT/PacBio reads。评估组装图、重复和连接后，才进入 FASTA-only 注释路线。组装失败、图有多解或技术类型不受当前工具支持时，报告应停止在候选/证据不足状态；不得仅凭工具成功退出或单一环状输出宣称完整正确。

## 修改与验证

原始输入保持不变。每个修改需在报告中记录对象/坐标、原值、新值、依据、置信度和验证结果；中间 `manifest`、命令、日志与机器可读任务记录放在 `intermediate/`。按修改类型重跑检查：

- 碱基更改重新核对独立 reads、碱基质量、方向、模板和竞争解释。
- 结构更改验证每个新增连接、原有邻接和闭合位置；不能分辨的候选继续并列。
- 注释更改重新检查序列坐标、翻译读框、起止密码子、tRNA 身份/反密码子及 feature 重叠。
- GFF3 使用 validator 检查语法与唯一 ID，并对照 GenBank 的主要 feature 坐标、链向和 CDS phase。N 区应明确表示为 gap 或清楚标出，不填造序列。

## 结果状态

只有当影响序列、基因身份、关键边界或生物学解释的问题均由适当证据解决，才称为完成版。否则照样交付四个文件，但把状态明确标成“最佳当前候选”或“受阻”，并指出证据缺口及其后果。不要为了文件看起来完整而填充无依据的碱基、裁切 feature，或把自动注释升级为专家定稿。
